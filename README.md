## 1. サービス概要
本アプリは、前職の英会話スクールで感じた「宿題に関する問い合わせ対応数を減らす」目的で開発した、英会話スクール専用の宿題管理アプリです。
- 生徒は、いつでも自分の宿題・授業プリントを確認でき、毎週取り組むべき学習内容を自身で管理できます。
- 保護者は、欠席した時や振替授業の時でも、宿題を確認する問い合わせをする必要はありません。
- 講師側は、宿題やテスト範囲等をオンライン上で一元管理できるため、印刷業務や問い合わせ対応の負担を軽減できます。
このように、本アプリは生徒・保護者・講師の３者それぞれの課題を解決し、生徒の学習の効率化と講師の業務負担の軽減を実現するアプリです。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情
本アプリを開発しようと思ったきっかけは、前職の英会話スクールでの勤務経験です。

スクールでは毎週必ず宿題が出ることになっており、生徒は自習の授業までに宿題の単語テストを宿題としてやってくるというシステムになっています。
スクールでは主に英検の取得級でクラスが編成されており、17時から19時までは小学生クラス。19時半から21時半までが中高生クラスと分かれます。

小学生クラスに関しては、ひと月分の宿題の範囲が記載されたをプリントで一人ひとり配布します。
一方で中高生クラスでは、ノートに書かせて宿題を管理するアナログなシステムを採用していました。

一見、特に不便さを感じるように思えないかもしれませんが、現場では、以下のような課題がありました。

## 1. 生徒が欠席してしまうと、次の週の宿題内容がわからなくなってしまう

生徒が授業を欠席すると、次回までに取り組むべき宿題が分からなくなります。
その際、小学生の場合は、その保護者が校舎へ電話をかけて確認する必要があり、その都度スタッフは確認したり、
必要に応じて連絡アプリを通じて宿題内容を送信したりしていました。

中高生の場合は、本人が電話をして確認したり、授業前早めにきて確認しに来る生徒もいましたが、生徒の中には「先週休んだから宿題はわからない。だからやらなくてもいい」と考え、欠席しても次の週の宿題を確認せずに翌週のレッスンに出席するケースも見られました。
その場合、生徒は宿題となっている単語テストを一切やらずにレッスンを受ける為、他の生徒との学習に差が生まれてしまいます。

こうした宿題に関する問い合わせは、毎月頻繁に色々な生徒の保護者から寄せられます。
授業準備や他業務を行っているスタッフにとっては、進行中の作業が一度止まるため、非常に負担であると感じていました。

## 2. 宿題内容の修正対応が講師やスタッフにとって負担

小学生に配布する宿題プリントはカリキュラム作成者が行い、事前にダブルチェックを行った上で生徒に配布していました。
しかし宿題配布後にミスが発覚したり、カリキュラム作成者から内容の修正メールが来ることも頻繁にありました。
その場合、講師は授業内で該当クラス全てきに口頭説明を行うか、修正版を再印刷して生徒へ配布しなければなりませんでした。
修正の度に追加対応が発生し、講師・生徒双方に負担がかかっていました。

## 3. 印刷コストが毎月発生する

小学生クラスの宿題プリントは毎月配信されるカリキュラムに合わせて作成・印刷されます。
現場では担当講師が印刷を担当していましたが、印刷枚数が不足すると困るため、多めに印刷するケースが少なくありませんでした。

また、前職では全16校舎あり、１校舎に小学生は約150人以上通っています。毎月宿題プリントを印刷していることを考えると、
用紙代やインク代などの印刷コストも無視できない課題でした。

## 4. 月例単語テストの運用にも課題

前職の英会話スクールでは、毎月末に総まとめの単語テストを実施していました。
テスト範囲は担当講師が範囲表を印刷して配布するか、授業内でまとめテストの範囲をノートに記入させる形で伝えていました。

しかし、宿題管理と同様に、

- 急にテスト範囲の修正が発生する
- 講師が範囲を伝え忘れる
- 生徒が欠席した場合、範囲を把握できない

といった問題が頻繁に起こっていました。

その結果、生徒がテスト当日に初めて範囲を知るケースもあり、十分な準備ができないまま受験することもありました。

このように、宿題や単語テストの管理を紙ベースで行う運用には、

- 情報修正時の対応負担
- 印刷コスト
- 欠席者への情報共有
- 講師側の管理工数

といった課題がありました。

そこで私は、「生徒がいつでも自分の所属クラスのやるべき宿題を確認でき、講師側も一元管理できる仕組みがあれば、
双方の負担を大きく軽減でき、会社のコスト削減につながるのではないか」と考え、本アプリの開発を決意しました。

### 2-2. なぜそれが「気になった」のか
### 1. 保護者からの宿題確認の問い合わせを減らしたい

前職の英会話スクールでは、宿題に関する問い合わせが日常的に発生します。

例えば、
- 欠席したので翌週までの宿題範囲を教えてほしい
- 振替授業に参加するので宿題範囲を確認したい
- 宿題プリントを紛失したため再送してほしい

といった内容です。これらの問い合わせがある度に、スタッフはクラスファイルを確認しなければなりません。
また、宿題プリントの再送を依頼された場合は、資料をPDF化し、連絡アプリを通じて送信する必要があるため、
対応工数が多く、それだけで15分ほど取られることもあり、現場の講師やスタッフにとって非常に負担であると感じていました。

### 2. 生徒の「宿題がわからなかったから、やらなかった」をなくしたい

スクールでは毎週宿題が出されますが、生徒が欠席した場合、「欠席したから次やるべき宿題の内容がわからなかった」
という理由で宿題を行わずに次回の授業へ参加するケースが少なくありません。
しかし、宿題の単語テストはその週の授業で扱う長文から抜粋して作成されています。
そのため、宿題を行わないまま授業を受けると、単語がわからないので、授業の理解度にも影響を与えます。

### 3. 宿題をやることが生徒たちの日々の英語力向上につながる。

私自身の指導経験から、毎週の宿題の単語テストの準備を継続して行う生徒ほど、英検で合格する確率が高い傾向にあります。
英語力は短期間で身につくものではなく、日々の積み重ねによって向上します。
そのため、生徒が継続的に宿題へ取り組める環境を整えることは非常に重要です。

### 4. 無駄な印刷を減らしたい。

業務では、宿題プリントや授業で使用する教材を日常的に大量印刷しています。
特に、生徒へ配布する宿題プリントは、配布時に不足することがないよう、生徒数よりも少し多めに印刷する運用となっています。
余ったプリントは裏紙として保管していますが、毎週印刷が発生するため、使用しきれない裏紙が増え続けているのが現状です。

また、宿題内容の変更や修正が発生した場合には、印刷済みのプリントが使用できなくなり、廃棄せざるを得ないケースもあります。
その結果、紙の無駄や印刷コストの増加につながっています。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと
1. 宿題を確認する電話が多い
2. 保護者が校舎にわざわざ問い合わせる手間を減らしたい。
3. 講師、スタッフの負担を少しでも減らしたい
4. 印刷の無駄を減らしたい

### 3-2. 本当に解決したい課題は何か
1. 生徒自身が自主的に宿題を行なってほしい
2. 生徒が「何をすればいいか」を自分で判断できる自律的な学習習慣を育てたい
3. 生徒に日常的に宿題へ取り組んでほしい。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)
### 導入に関して
  1. まずはテスト運用として、スクールに通う一部の生徒に実際に利用してもらい、
  利用状況の分析や操作性に関するフィードバックの収集を行う。
  2. 収集した意見をもとに機能改善やUI/UXの調整を実施し、より学習しやすいアプリへと改善していく予定。
  3. その後、全校の生徒を対象に展開し、全16校舎で生徒向けのアプリのプレゼンを行う。

### 本アプリの利用を定着させるために
  1. ユーザーである生徒にアプリを通じてどのように学習するかを体験してもらう。
  2. 講師にも実際に使用してもらい、アプリの操作・使用方法についてプレゼンを行う。

### 本アプリを実際に導入してもらうために
本アプリを実際の英会話スクールに導入してもらうためには、単に機能を提供するだけでなく、
運営側が抱える懸念を解消する必要があります。

### 1. 現場の講師に価値を感じてもらう

どれだけ便利なシステムであっても、現場の講師が必要性を感じなければ導入には至りません。

本アプリでは、

- 宿題確認の電話対応を削減できる
- 欠席者への宿題共有を自動化できる
- 宿題プリントの印刷業務・コストを減らせる
- 生徒への宿題伝達漏れを防げる

といったメリットがあります。
そのため、「どの業務をどの程度削減できるのか」を具体的に示し、
現場の負担軽減につながることを伝える必要があります。

### 2.生徒の個人情報を安全に管理する

スクールで利用するシステムでは、生徒や保護者の個人情報を扱うため、
セキュリティ対策は不可欠です。そのため、

- 個人アドレスではなく、生徒IDでの管理
- 退会したら、アクセス権限をなくす

などを行い、安全に利用できるシステムであることを示す必要があります。

### 3. コスト削減効果を可視化する

スクール側が導入を判断する上では、費用対効果も重要な要素です。

本アプリを導入することで、

- 宿題プリントの印刷コスト
- 月例単語テスト範囲表の印刷コスト
- 電話対応にかかる人件費

を削減できます。

### 5-2. それでも自分が作りたい理由
### 既存サービスとの違い
- 既存のBus Catch（連絡アプリ）は出席管理・保護者連絡といった運営業務の効率化が中心であり、
宿題の内容・進捗に特化した機能は存在しない。
- 宿題のメールを保護者に送ることは可能ではあるが、各校舎ごとに宿題を送信すると、
対応工数が多くなり各校舎の講師に負担がかかる。

### 開発の背景
実際に現場で働いていた講師としての経験から、電話対応をはじめとするスタッフの業務負担が大きいという課題を実感し、
既存システムでは解決できない宿題管理の現場ニーズに応えるために開発しました。

### 差別化ポイント
- 宿題の内容・進捗管理に特化
- 講師側：宿題に関する電話対応を削減、印刷コストの削減、
- 生徒側：自分のやることが明確になり、学習習慣をサポート
- 保護者側：子供の宿題を一緒に確認できる、宿題の進捗状況がわかる。
- 現場経験者が作った、現場目線のアプリ

### 5-3. 差別化を一文で決める
- 私のアプリの差別化ポイント：「宿題を出す側も、こなす側も、もっとラクになる宿題管理アプリ」

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- 行動の変化：
  
  - 欠席した場合でも、自らアプリで宿題を確認し取り組むようになる。
  - 宿題や単語テスト範囲を定期的に確認する習慣が身につく。
  - 保護者が校舎へ問い合わせることなく、必要な情報を確認できるようになる。
  - 宿題のやり忘れやテスト範囲の確認漏れが減る。
  - 日常的に宿題へ取り組む機会が増える。
  
- 気持ちの変化：

  - 「宿題がわからない」というストレス・不安がなくなる。
  - 欠席しても学習の遅れを最小限に抑えられるという安心感を持てる。
  - 保護者も子供のやる宿題を確認できるため、安心して子どもの学習を見守れる。
  - 講師は問い合わせ対応や宿題管理の負担が減り、本来の指導業務に集中できるようになる。
  
- 考え方の変化：
  
  - 「先生に聞かないと宿題がわからない」から、「自分で確認して学習を進める」へ変わる。
  - 宿題を受け身でこなすものではなく、自分の学習を支えるものとして捉えられるようになる。
  - 保護者は「校舎に問い合わせる」から「必要な情報はアプリで確認する」という行動に変わる。
  - スクール側は紙中心の運用から、デジタルを活用した効率的な学習管理へと考え方が変化する。

## 8. このアプリの懸念点とその対策
### 懸念点①

- 何が問題になりそうか：全校生徒数千人規模で利用した場合、アプリ上で負荷や不具合が発生する可能性がある。
- なぜそう思うか：同時に集中することで、サーバー負荷の増加やレスポンス遅延が起こる可能性があるため。
- そのために考えている対策：段階的リリース（テスト運用→一部クラス→全校展開）を行う。

### 懸念点②

- 何が問題になりそうか：携帯を持っていない小学生や制限がかかっている携帯の場合、保護者がいないと宿題ができない状況が生まれる。
- そのために考えている対策：そうした生徒には紙ベースで、宿題を配布する。

### 10-1. 使用技術
| 項目 | 技術 |
|------|------|
| フロントエンド | HTML / CSS / JavaScript |
| バックエンド | Ruby |
| フレームワーク | Ruby on Rails |
| 認証 | Devise |
| 環境構築 | Docker |
| データベース | PostgreSQL |

| その他 | Bootstrap / rubocop / AdminLTE（管理画面のCSSフレームワーク）

### 10-2. 技術選定の理由

#### 【バックエンド】
Ruby / Ruby on Rails
Railsの「設定より規約」という原則により、アプリケーションの詳細な設定を大幅に減らせて、開発時間を短縮できると思ったため採用しました。
また、RailsはWebアプリケーションに必要な標準機能（Gemなど）を提供しており、迅速にアプケーションを構築できると思いました。

- **開発速度が速い**：「設定より規約（Convention over Configuration）」の考え方により、少ないコード量で開発できるため。
- **学習コストが低い**：Rubyは自然言語に近い文法で可読性が高く、初学者でも理解しやすい。
- **AIとの相性が良い**：Ruby on Railsは利用者が多く、AIによるコード補完やエラー解析の精度が高いため。
- **豊富なGem（ライブラリ）が利用できる**：DeviseやRansackなどのGemを活用することで、認証や検索機能などを効率的に実装できるため。
- **MVCアーキテクチャを採用している**：役割ごとにコードを分離でき、保守性・拡張性の高いアプリケーションを開発できるため。

#### 【インフラ】
Docker
- **環境構築を容易にするため**: `docker compose up` を実行するだけで、RailsやPostgreSQLなどの必要なサービスをまとめて起動できるため。

#### PostgreSQL

- **Ruby on Railsとの親和性が高いため**：Railsで広く利用されており、公式ドキュメントやチュートリアルでも採用例が多く、安心して利用できるため。

- **高い信頼性と安定性を備えているため**：データの整合性を保つ機能が充実しており、本番環境でも多くのWebサービスで利用されているため。
